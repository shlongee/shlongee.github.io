Яркие объекты выглядят плоскими без мягкого света вокруг.<br/>
Вот как я собрал быстрый проход HDR-bloom в [Raylib](/ru/tags/raylib/) и избавился от 8-битного бэндинга:

## 1. Цепочка Bloom из 5 мипов (13-Tap Blur)
Вместо одного тяжёлого гигантского размытия мы пять раз сжимаем яркие пиксели и плавно смешиваем их обратно:

* **Prefilter:** отбираем пиксели выше мягкого порога *(soft-knee)*.
* **Downsample:** 5× уменьшаем кадр 13-выборочным фильтром.
* **Upsample:** поочерёдно возвращаем и накладываем каждый мип на кадр.

```glsl
// Плавный порог (soft-knee) для выделения ярких областей
vec3 softThreshold(vec3 color, float threshold, float knee) {
  float br = max(color.r, max(color.g, color.b));
  float soft = clamp(br - threshold + knee, 0.0, 2.0 * knee);
  soft = (soft * soft) / (4.0 * knee + 1e-5);
  float contrib = max(soft, br - threshold) / max(br, 1e-5);
  return color * contrib;
}
```

## 2. Баги: BeginDrawing() и #version 330
1. **Двойной `BeginDrawing()`:**<br/>
Если вызвать функцию и в `ApplyBloom()`, и в `main()`, то FPS уменьшается вдвое, а изображение начинает мигать.
2. **Забытый `#version 330`:**<br/>
Отсутствие этой строки в фрагментном [GLSL](/ru/tags/glsl/)-шейдере мешает обновлению uniform-переменных в `compositeFS`.

## 3. Почему Float16 убирает 8-битный бандинг
8-битный канал `(R8G8B8A8)` хранит всего 256 фиксированных шагов `(1/255)`,
от чего тусклые края ореола превращаются в ступеньки, а сильный bloom раздувает их в резкие кольца.

Float16 `(R16G16B16A16)` упаковывает крошечные экспоненты у нуля, сохраняя плавный [HDR](/ru/tags/hdr/)-свет даже на самом краю затухания:

## 4. Замеры GPU в 720p
* **Стоимость 720p (Intel UHD):** ~0.52 мс на кадр.
* **`R16G16B16A16` против `R8G8B8A8`:** +0.08 мс.
